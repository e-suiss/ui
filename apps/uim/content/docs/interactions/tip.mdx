`Tip` shows a hint until the user dismisses it, then records the dismissal under its `id` so it does not return. It renders either as a `TipCard` placed in the layout, or as a `TipPopover` with an arrow pointing at a `TipAnchor`. Touching the anchor also dismisses the tip.

`TipGroup` shows several tips one at a time in the order they mount, moving to the next when one is dismissed. Use tips to introduce a feature or gesture the user may not discover.

## Usage

<Code lang="tsx" code={"import { TipGroup, Tip, TipCard, TipAnchor, TipPopover, TipIcon, TipContent, TipTitle, TipDescription, TipClose } from \"@/components/interactions/tip\""} />

<Code lang="tsx" code={"<TipsExample fresh />"} />

Give each `Tip` a stable `id`. Compose `TipIcon`, `TipContent` with `TipTitle` and `TipDescription`, and `TipClose` inside a `TipCard` or `TipPopover`. For a popover, wrap the target in `TipAnchor` inside the same `Tip`.

By default dismissals are kept in memory and reset when the app restarts. To persist them, pass a `storage` adapter to `TipGroup` with `getItem` and `setItem`, sync or async, such as one backed by your app's key-value store. Keys are prefixed with `tip:`. `resetTips(ids, storage)` clears dismissals, and `useTip` returns `visible` and `dismiss`. The `TipStorage` type is exported.

## Accessibility

- `TipCard` has the `note` role.
- `TipPopover` is non-modal, does not move focus, and is labelled by `TipTitle`.
- `TipClose` is labelled `Dismiss tip`.
- The icon is hidden from screen readers.

## Notes

- Cards use `bg-surface-secondary`; popovers use `bg-surface-raised` with a border that is stronger in dark mode, and are up to 320 points wide.
- Animations respect the system reduce motion setting.
- On iOS the popover renders in a full-window overlay so it appears above native screens.
