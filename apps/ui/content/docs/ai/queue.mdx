Queue is the agent's todo list. Todos sit in two sections, To do and Completed, and the icon on each todo shows its status. The agent updates the list as it works, so a todo moves from one section to the other when it is done.

Each section is a `TraceCollapsible` with a nested `Trace` of todos. For steps the agent decides on up front, use [Plan](/docs/ai/plan); for steps it takes as it goes, use [Task](/docs/ai/task).

## Installation

Queue is built with the [Trace](/docs/components/trace) component.

```bash title="Terminal"
npx shadcn@latest add @esuiss/trace
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

```bash title="Terminal"
npx @esuiss/ui@latest add trace
```

Map each todo status to a section, an icon and a `TraceLine` status:

| Todo status | Section | Icon | `TraceLine` status |
| --- | --- | --- | --- |
| `pending` | To do | Circle | — |
| `in_progress` | To do | Circle with a dot | `running` while the agent works |
| `completed` | Completed | Circle with a check | — |

### Descriptions

A todo with a description is a `TraceCollapsible` that opens to show it. A todo without one stays a `TraceLine`.

## AI SDK

The agent writes its todos with a tool, `writeTodos` in this example. Each call sends the whole list, so render the last call and skip one whose input is still streaming.

```tsx
const todos = message.parts
  .filter((part) => part.type === "tool-writeTodos")
  .filter((part) => part.state !== "input-streaming")
  .at(-1)?.input?.todos
```

Set `running` on the todo in progress only while the chat streams, so its title stops shimmering when the agent stops.
