`SwipeActions` recreates iOS swipe actions for list rows. Dragging `SwipeActionsContent` sideways reveals the buttons in `SwipeActionsActions` on that side; releasing past half their width snaps the row open, otherwise it springs closed. Dragging past the actions meets increasing resistance, unless an action has `fullSwipe`: then dragging past 60% of the row width expands that action across the row, and releasing collapses the row and runs it.

Only one row stays open at a time. Tapping the content or pressing elsewhere closes an open row, and choosing an action closes it after the action runs. Use it for quick per-row actions such as archive, delete, or mark as unread.

- Place `SwipeActionsContent` inside `SwipeActions`, with a `SwipeActionsActions` for each side that has actions. Rows can have leading actions, trailing actions, or both.
- Handle each action with `onClick`. A full swipe runs the action by clicking it, so the same handler covers both.
- `useSwipeActions` returns `close` for closing the row from custom controls.
- Gestures are detected with pointer events and locked to the horizontal axis after a few pixels, so vertical scrolling still works.

## Accessibility

- The row has `role="group"`, and actions are native buttons that stay in the tab order.
- Moving focus to an action opens its side of the row so the button is visible; moving focus out of the row closes it.
- `Escape` closes an open row.
- Leading and trailing sides follow the writing direction, so swipes mirror in right-to-left layouts.

## Notes

- The root uses `data-slot="swipe-actions"` and sets `data-open` (`leading` or `trailing`), `data-full` during a full swipe, and `data-removing` while the row collapses. Action groups expose `data-side`, and full-swipe actions set `data-full-swipe`.
- The `--swipe-actions-offset` custom property holds the current offset.
- `swipeActionVariants` is exported for styling other elements like an action.

`SwipeActions` wraps a row so it can be dragged left or right to reveal `SwipeAction` buttons on the leading or trailing side. The buttons stretch to fill the revealed space, and opening one row closes any other open row.

When an action has `fullSwipe`, dragging past 60% of the row width expands that action over the others with a medium impact haptic. Releasing there slides the row off, collapses its height, then runs the action, which suits delete or archive. Use it for mail, message or task lists.

Put the row in `SwipeActionsContent`, and the buttons in one `SwipeActionsActions` per side, with `side` set to `leading` or `trailing` (the default). Leading actions are on the left in left-to-right layouts and on the right in right-to-left layouts.

Pressing an action runs `onPress` and closes the row. For a full-swipe action, `onPress` runs after the row collapses, so remove the item from your data there. `useSwipeActions` returns `close` for closing the row from inside it. `swipeActionVariants` is also exported.

## Accessibility

- Every action is offered as an accessibility action on `SwipeActionsContent`, labelled by its `accessibilityLabel` or text, so screen reader users can run it without swiping.
- Hidden actions are removed from the accessibility tree until their side is open.
- The row has the `group` role and each action the `button` role.

## Notes

- The full-swipe haptic plays only if the app provides an adapter through `HapticsProvider`.
- Action colors use `bg-accent`, `bg-danger`, `bg-purple` and `bg-gray` with `text-on-accent` labels and icons; the content uses `bg-surface`.
