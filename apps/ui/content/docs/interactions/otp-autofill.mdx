`OtpAutofill` builds on the suiss/ui `InputOTP` component to recreate the iOS security code autofill flow. When the field is focused and empty, `OtpAutofillSuggestion` offers the received code; choosing it types the digits in with a short pop animation and calls `onVerify` once all slots are filled. A valid code turns the slots green and locks the field; an invalid one shakes the slots, marks them red, then clears the field and refocuses it.

The suggestion adapts to the device through `useIsMobile`. Below `48rem` it docks above the on-screen keyboard like the QuickType bar, tracking the visual viewport; on wider screens it appears as an inline pill under the field. In supporting browsers, the WebOTP API also reads codes from SMS and fills them automatically.

## Usage

```tsx
import { OtpAutofill, OtpAutofillInput, OtpAutofillSuggestion } from "@/components/interactions/otp-autofill"
```

```tsx
<VerificationExample incoming={CODE} />
```

- Place `OtpAutofillInput` and `OtpAutofillSuggestion` inside `OtpAutofill`. Pass `InputOTPGroup`, `InputOTPSlot`, and `InputOTPSeparator` from `input-otp` as the input's children.
- The value is managed internally. Typing or pasting also verifies automatically once the code reaches `maxLength`; a paste of several characters fills with the same animation.
- `onVerify` may be async. Use `useOtpAutofill` to read `state` (`idle`, `filling`, `verifying`, `verified`, `invalid`) for status text or other UI.
- Set `code` on the suggestion to `null` until a code arrives; the suggestion stays hidden without one.

## API Reference

<ApiPart index={1}>

### OtpAutofill

The root that holds the code value and verification state.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `maxLength` | `number` | Required | The number of characters in the code; verification runs once it is reached. |
| `onVerify` | `(code: string) => Promise<boolean> \| boolean` | Required | Called with the complete code; return or resolve `true` to accept it or `false` to reject it. |
| `webOtp` | `boolean` | `true` | Listens for SMS codes through the WebOTP API, where supported. |

Also accepts the props of `React.ComponentProps<"div">`.

</ApiPart>

<ApiPart index={2}>

### OtpAutofillInput

The `InputOTP` field wired to the autofill state.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `containerClassName` | `string` | - | Classes for the slot container, merged with the state styles. |
| `children` | `React.ReactNode` | Required | The slot groups and separators that make up the field. |

Also accepts the props of `React.ComponentProps<"input">`.

</ApiPart>

<ApiPart index={3}>

### OtpAutofillSuggestion

The button that offers the received code and fills it when pressed.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `code` | `string \| null \| undefined` | Required | The received code to offer; the suggestion is hidden while it is empty. |
| `source` | `React.ReactNode` | `"From Messages"` | The label that names where the code came from. |

Also accepts the props of `React.ComponentProps<"button">`.

</ApiPart>

## Accessibility

- Label the field with `aria-label` on `OtpAutofillInput`, which renders a single text input.
- The input is read-only while filling, verifying, or verified, and sets `aria-invalid` when the code is rejected.
- The suggestion is a native button that is `inert` while hidden, and it prevents focus from leaving the field on press.
- After a rejected code, focus returns to the field. Pair the root with a `role="status"` element to announce the result.

## Notes

- The root exposes `data-slot="otp-autofill"` and `data-state`. The suggestion uses `data-slot="otp-autofill-suggestion"`, `data-placement` (`keyboard` or `inline`), and `data-closed` while hidden.
- The pop and shake animations are skipped under `prefers-reduced-motion`.

`OtpAutofill` wraps an `InputOTP` and runs it through `idle`, `filling`, `verifying`, `verified` and `invalid` states. When the input is focused and empty, `OtpAutofillSuggestion` slides up above the keyboard with the incoming code; pressing it types the code one digit at a time.

When all digits are entered, `onVerify` runs and the slots dim while it is pending. A valid code turns the slots green and locks the input. An invalid code turns them red and shakes the row, then clears the input and refocuses it. Pasting or a system autofill of several digits plays the same digit-by-digit fill.

## Usage

```tsx
import { OtpAutofill, OtpAutofillInput, OtpAutofillSuggestion } from "@/components/interactions/otp-autofill"
```

```tsx
<VerificationExample incoming={CODE} />
```

Pass `maxLength` and `onVerify`, which returns a boolean or a promise of one. Put `InputOTPGroup` and `InputOTPSlot`s inside `OtpAutofillInput`, and render an `OtpAutofillSuggestion` with the `code` your app received; it hides when `code` is empty.

The input sets `textContentType="oneTimeCode"` and the platform's one-time code `autoComplete`, so the system can also offer the code. `useOtpAutofill` returns `state`, `value`, `fill` and `inputRef` for custom controls.

## Accessibility

- `accessibilityLabel` on `OtpAutofillInput` is passed to the underlying text input.
- The suggestion bar has the `button` role.
- The input is read-only while filling, verifying and after a valid code.

## Notes

- Invalid slots use `border-destructive` with a `bg-destructive` tint that is stronger in dark mode; verified slots use `border-green-500` and `bg-green-500/10 dark:bg-green-500/20`.
- The suggestion bar uses `bg-popover`, or `bg-muted` in dark mode, and sits on the keyboard or above the bottom safe area.
- Slide and shake animations respect the system reduce motion setting.
