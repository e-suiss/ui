A trusted-device sign-in flow with instructions on one side and a simulated approval alert on the other, which shows a verification code after Allow and a blocked message after Don't Allow. The user then types the code to finish. The columns sit side by side on desktop and stack on mobile. Use it to illustrate or build sign-in approval from a second device.

## Installation

### CLI

```bash title="Terminal"
npx shadcn@latest add @esuiss/verify-device
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

```bash title="Terminal"
npx @esuiss/ui@latest add blocks verify-device
```

### Manual

1. Install the dependencies:

```bash title="Terminal"
npm install @phosphor-icons/react
```

2. Add the pieces it builds on: [Input OTP](/docs/components/input-otp), [Spinner](/docs/components/spinner).

3. Copy the source into `components/blocks/verify-device.tsx`:

<ComponentSource path="components/blocks/verify-device.tsx" />

4. Update the import paths to match your project.

## Usage

```tsx
import { VerifyDevice } from "@/components/blocks/verify-device"
```

```tsx
<VerifyDevice />
```

In a real flow the approval alert appears on the user's other device, so remove the simulated alert and poll or subscribe for the approval instead. Replace the `DEMO_CODE` check with your verification API, and edit the per-phase text in `copy`. Swap the `backdrop` image and the location text.

The screen shows a mock alert from the trusted device with Allow and Don't Allow. Allowing reveals a code and an `InputOTP` to enter it, with a `Spinner` while checking and an error for a wrong code; denying shows a blocked message with an option to show the request again. A correct code shows an approved screen.
