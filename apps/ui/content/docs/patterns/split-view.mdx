`SplitView` arranges content in up to three columns, like Mail: a sidebar, a list and a detail pane. On desktop it places the panes in a horizontal suiss/ui `ResizablePanelGroup` with resize handles between them. The panes default to 20%, 32% and 48% of the width, with minimum sizes of 15%, 22% and 30%.

On mobile (below `48rem`, via `useIsMobile`) only one column shows at a time. Tapping a `SplitViewItem` pushes the next column, and a back button labelled with the previous pane's title returns to it. After navigation, focus moves to the new pane's heading and the view scrolls into place. Use it for master-detail interfaces such as mail, settings or file browsers.

## Installation

### CLI

```bash title="Terminal"
npx shadcn@latest add @esuiss/split-view
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

## Usage

```tsx
import { SplitView, SplitViewSidebar, SplitViewList, SplitViewDetail, SplitViewItem } from "@/components/patterns/split-view"
```

```tsx
<MailExample />
```

- Place `SplitViewSidebar`, `SplitViewList` and `SplitViewDetail` as direct children of `SplitView`. Leave out the sidebar for a two-column layout.
- The mobile column is uncontrolled by default and starts at `defaultColumn`. Use `column` with `onColumnChange` to control it.
- `SplitViewItem` advances to the next column on click and runs your own `onClick` too. Set `isActive` on the current item.
- The list pane shows a back button to the sidebar only when the sidebar has a `title`.
- `useSplitView` returns `isMobile`, `column` and `setColumn` for custom navigation inside the view.

## API Reference

<ApiPart index={1}>

### SplitView

The root that lays out the panes and tracks the visible mobile column.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `column` | `SplitViewColumn` | - | The visible mobile column when controlled: `sidebar`, `list` or `detail`. |
| `defaultColumn` | `SplitViewColumn` | `"list"` | The mobile column shown first when uncontrolled. |
| `onColumnChange` | `(column: SplitViewColumn) => void` | - | Called with the new column when navigation changes it. |

Also accepts the props of `React.ComponentProps<"div">`.

</ApiPart>

<ApiPart index={2}>

### SplitViewSidebar

The leading pane, usually for sources or categories.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `React.ReactNode` | - | The pane heading and accessible name; also labels the back button in the list pane. |

Also accepts the props of `React.ComponentProps<"section">`.

</ApiPart>

<ApiPart index={3}>

### SplitViewList

The middle pane, usually a list of items.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `React.ReactNode` | - | The pane heading and accessible name; visually hidden on desktop and used for the back button in the detail pane. |

Also accepts the props of `React.ComponentProps<"section">`.

</ApiPart>

<ApiPart index={4}>

### SplitViewDetail

The trailing pane that shows the selected item.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `React.ReactNode` | - | The pane heading and accessible name. |

Also accepts the props of `React.ComponentProps<"section">`.

</ApiPart>

<ApiPart index={5}>

### SplitViewItem

A button row that marks the current selection and advances to the next column on mobile.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `isActive` | `boolean` | `false` | Marks the item as the current selection with `aria-current` and `data-active`. |

Also accepts the props of `useRender.ComponentProps<"button">`, `React.ComponentProps<"button">`.

</ApiPart>

## Accessibility

- Each pane is a `section` labelled by its `title` heading, so titled panes are exposed as regions.
- The active item has `aria-current="true"`.
- On mobile, navigating moves focus to the new pane's heading. The back button's chevron is hidden from assistive technology.

## Notes

Styling hooks: `data-slot="split-view"`, `split-view-sidebar`, `split-view-list`, `split-view-detail`, `split-view-back` and `split-view-item`; desktop panels use `split-view-sidebar-panel`, `split-view-list-panel` and `split-view-detail-panel`. On mobile the root has `data-column` set to the visible column.

`SplitView` lays out up to three panes: `SplitViewSidebar`, `SplitViewList` and `SplitViewDetail`. When the window is at least `breakpoint` wide (768 by default), they sit side by side in a bordered row, sized 20, 32 and 48 parts.

Below the breakpoint only the current column is shown, full screen and scrollable, with a large title. Pressing a `SplitViewItem` moves to the next column, and a back button titled with the previous pane returns to it. On Android the hardware back button also goes back. Use it for mail, notes or settings screens that drill down.

## Usage

```tsx
import { SplitView, SplitViewSidebar, SplitViewList, SplitViewDetail, SplitViewItem } from "@/components/patterns/split-view"
```

```tsx
<MailExample />
```

Give each pane a `title`; the back button only appears when the previous pane exists and has a title. Put `SplitViewItem`s in the sidebar and list panes, and use their `onPress` to set the selection in your own state.

The current column is uncontrolled with `defaultColumn` (`list` by default) or controlled with `column` and `onColumnChange`. `useSplitView` returns `isCompact`, `column` and `setColumn` for custom navigation.

## API Reference

<ApiPart index={1}>

### SplitView

The root that tracks the current column and the layout mode.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `column` | `SplitViewColumn` | - | The visible column on phones when controlled: `sidebar`, `list` or `detail`. |
| `defaultColumn` | `SplitViewColumn` | `"list"` | The initial column when uncontrolled. Defaults to `list`. |
| `onColumnChange` | `(column: SplitViewColumn) => void` | - | Called with the new column. |
| `breakpoint` | `number` | `768` | Window width at which the panes sit side by side. Defaults to `768`. |

Also accepts the props of `ViewProps`.

</ApiPart>

<ApiPart index={2}>

### SplitViewSidebar

The first pane, for top-level sections.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `React.ReactNode` | - | The title shown at the top of the column. |

Also accepts the props of `SplitViewPaneProps`.

</ApiPart>

<ApiPart index={3}>

### SplitViewList

The middle pane, for the items in a section.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `React.ReactNode` | - | The title shown at the top of the column. |

Also accepts the props of `SplitViewPaneProps`.

</ApiPart>

<ApiPart index={4}>

### SplitViewDetail

The last pane, for the selected item.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `React.ReactNode` | - | The title shown at the top of the column. |

Also accepts the props of `SplitViewPaneProps`.

</ApiPart>

<ApiPart index={5}>

### SplitViewItem

A pressable row that moves to the next column.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `isActive` | `boolean` | `false` | Highlights the row and marks it as selected. |
| `children` | `React.ReactNode` | - |  |

Also accepts the props of `React.ComponentProps<typeof Pressable>`.

</ApiPart>

## Accessibility

- Pane titles have the `heading` role, and panes are labelled by string titles.
- On phones, screen reader focus moves to the new pane's heading after navigating.
- `SplitViewItem` exposes its `selected` state.
- Back and row chevrons mirror in right-to-left layouts.

## Notes

- On phones the new pane fades in, respecting the system reduce motion setting.
- Active rows use `bg-muted`; panes are divided by `border-border`.
