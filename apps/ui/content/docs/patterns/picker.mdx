`Picker` lets the user choose one option from a short list. On desktop it renders a suiss/ui `Select` with a trigger, a popup list, labelled groups and separators. On mobile (below `48rem`, via `useIsMobile`) it renders a `NativeSelect`, so the platform's own picker wheel or sheet appears; groups become `optgroup` elements and separators are omitted.

You describe options once with `PickerItem`, `PickerGroup` and `PickerSeparator`, and the same markup drives both presentations. Use it for form fields where the options are known and do not need search; for long lists, use `SearchPicker`.

## Usage

<Code lang="tsx" code={"import { Picker, PickerGroup, PickerItem, PickerSeparator } from \"@/components/patterns/picker\""} />

<Code lang="tsx" code={"<Picker placeholder=\"Select a fruit\" aria-label=\"Fruit\" className=\"w-48\">{fruitItems}</Picker>"} />

- The value is uncontrolled by default; use `defaultValue`, or `value` with `onValueChange` to control it.
- `Picker` collects the value and label of each `PickerItem` from its children so the desktop trigger can show the selected label. Pass `items` only when options are not rendered as direct or nested `PickerItem` elements.
- `PickerGroup`, `PickerItem` and `PickerSeparator` must be used inside `Picker`, or they throw.
- Give the picker an accessible name with `aria-label` or a `Label` that points at its `id`.

## Accessibility

- The desktop trigger has the `combobox` role and opens a `listbox`; the selected option has `aria-selected`, and disabled options have `aria-disabled`.
- Labelled groups are exposed as `group` elements named by their label.
- Escape closes the desktop list without changing the value.
- On mobile the control is a native `select`, with the platform's built-in keyboard and screen reader support.
