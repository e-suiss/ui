`PagedList` slices an array of items into pages and renders each one through `renderItem` inside a plain list. On desktop it shows a suiss/ui `Pagination` with previous and next links, the first and last page, the pages next to the current one, and ellipses for the gaps. The pagination is hidden when everything fits on one page.

On mobile (below `48rem`, via `useIsMobile`), the list grows instead of paging: a full-width secondary `Button` appends the next page of items, and focus moves to the first newly loaded item. Use it for long feeds, search results or topic lists where the user moves through a known set of items.

## Usage

```tsx
import { PagedList } from "@/components/patterns/paged-list"
import { Item, ItemContent, ItemDescription, ItemTitle } from "@/components/ui/item"
```

```tsx
const topics = [
  { id: 1, title: "Getting started", replies: 12 },
  { id: 2, title: "Dark mode tokens", replies: 4 },
]

<PagedList
  items={topics}
  pageSize={10}
  getKey={(topic) => topic.id}
  renderItem={(topic) => (
    <Item>
      <ItemContent>
        <ItemTitle>{topic.title}</ItemTitle>
        <ItemDescription>{topic.replies} replies</ItemDescription>
      </ItemContent>
    </Item>
  )}
/>
```

- The current page is uncontrolled by default and starts at `defaultPage`. Pass `page` and `onPageChange` to control it.
- Out-of-range page values are clamped between `1` and the page count.
- Without `getPageHref`, page links use `#` and prevent navigation. With it, each link gets a real `href` and still updates the page on click.
- Provide `getKey` when items have stable IDs; the default key is the item's index.
- The mobile Load more state is internal and independent of `page`.

## API Reference

<ApiPart index={1}>

### PagedList

The root that renders the visible items and the pagination or Load more control.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `T[]` | Required | The full array of items to page through. |
| `pageSize` | `number` | `10` | The number of items per page, and per Load more step on mobile. |
| `page` | `number` | - | The current page when controlled. |
| `defaultPage` | `number` | `1` | The page shown first when uncontrolled. |
| `onPageChange` | `(page: number) => void` | - | Called with the new page number when the user changes pages. |
| `getPageHref` | `(page: number) => string` | - | Returns the `href` for a page link, turning pagination into real links. |
| `getKey` | `(item: T, index: number) => React.Key` | `(_, index) => index` | Returns the React key for an item. |
| `renderItem` | `(item: T, index: number) => React.ReactNode` | Required | Renders one item; receives the item and its index in `items`. |
| `loadMoreLabel` | `string` | `"Load more"` | The label of the mobile Load more button. |
| `previousLabel` | `string` | - | Visible text for the previous link; it also becomes its accessible name. |
| `nextLabel` | `string` | - | Visible text for the next link; it also becomes its accessible name. |
| `listClassName` | `string` | - | Classes applied to the inner list element. |

Also accepts the props of `React.ComponentProps<"div">`.

</ApiPart>

## Accessibility

- Items render in a `ul`, each inside its own `li`.
- The desktop pagination is a navigation landmark; the current page link has `aria-current="page"`.
- Previous and next links get `aria-disabled` on the first and last page. Their default accessible names are Go to previous page and Go to next page.
- Changing pages scrolls the list into view. Loading more on mobile moves focus to the first focusable element of the first new item.

## Notes

Styling hooks: `data-slot="paged-list"`, `paged-list-items`, `paged-list-item`, `paged-list-pagination` and `paged-list-load-more`. Because `renderItem` output is wrapped in an `li`, return row content such as an `Item`, not another list item.

`PagedList` takes the full `items` array and renders only the first `pageSize` items. When the user scrolls near the end, or presses the Load more button in the footer, the next page is appended.

The button disappears once every item is shown. Use it for long local lists where rendering everything at once is not needed.

## Usage

<Only platform="rn">

```tsx
import { ChatCircleIcon } from "phosphor-react-native"
import { PagedList } from "@/components/patterns/paged-list"
import { Icon } from "@/components/ui/icon"
import { Item, ItemContent, ItemDescription, ItemMedia, ItemTitle } from "@/components/ui/item"

type Topic = { id: number; title: string; replies: number }

const subjects = [
  "Getting started",
  "Dark mode tokens",
  "Form validation",
  "Release notes",
  "Accessibility",
  "Theming",
  "Server components",
  "Animations",
]

const topics: Topic[] = Array.from({ length: 57 }, (_, index) => ({
  id: index + 1,
  title: `${subjects[index % subjects.length]} · thread ${index + 1}`,
  replies: (index * 7) % 23,
}))

function TopicRow({ topic }: { topic: Topic }) {
  return (
    <Item onPress={() => undefined}>
      <ItemMedia variant="icon">
        <Icon as={ChatCircleIcon} />
      </ItemMedia>
      <ItemContent>
        <ItemTitle>{topic.title}</ItemTitle>
        <ItemDescription>{topic.replies} replies</ItemDescription>
      </ItemContent>
    </Item>
  )
}

export function PagedListExample() {
  return (
    <PagedList<Topic> items={topics} pageSize={10} getKey={(topic: Topic) => topic.id} renderItem={(topic: Topic) => <TopicRow topic={topic} />} />
  )
}
```

        items = items,

    Item(onClick = {}) {
        ItemMedia(variant = ItemMediaVariant.Icon) {
            Icon(PhosphorIcons.Regular.ChatCircle, contentDescription = null)

        ItemContent {
            ItemTitle(topic.title)
            ItemDescription("${topic.replies} replies")

    }

<Only platform="rn">

Pass `items`, `renderItem` and a `getKey` that returns a stable key for each item. `renderItem` receives the item and its index, not the `FlatList` info object.

Other `FlatList` props pass through, except `data`, `keyExtractor`, `onEndReached` and `ListFooterComponent`, which the list manages. Use `listClassName` to style the content container.

## Accessibility

- The Load more button is a `Button`, so screen reader users can load the next page without scrolling to the end.

## Notes

- The next page loads when the scroll position is within half a screen of the end (`onEndReachedThreshold` of `0.5`).
- The footer is a full-width `secondary` button.
