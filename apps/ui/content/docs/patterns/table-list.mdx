`TableList` displays rows of data from a column definition. On desktop it renders a suiss/ui `Table` inside a bordered section, with a header row and one cell per column. On mobile (below `48rem`, via `useIsMobile`), where wide tables do not fit, it renders an inset grouped list: each row shows a title line, a secondary line that joins description columns with a middle dot, and trailing values on the end.

Each column chooses its place in the mobile row through `slot`, and can provide a simpler `mobileCell`. Use it for orders, invoices, transactions and other records that people compare in columns on large screens.

## Usage

<Code lang="tsx" code={"import { TableList } from \"@/components/patterns/table-list\""} />

<Code lang="tsx" code={"<TableList<Order> rows={orders} columns={columns} getKey={(order: Order) => order.id} title=\"Orders\" className=\"mx-auto w-full max-w-3xl\" />"} />

- Each `TableListColumn` has a `key`, a `header` and a `cell` renderer. Optional fields are `mobileCell`, `slot` (`title`, `description`, `trailing` or `hidden`) and `align` (`start` or `end`).
- On mobile, the first `title` column becomes the primary line, `description` columns form the secondary line, and `trailing` columns appear at the end. Columns without a slot, or with `hidden`, are left out on mobile.
- `mobileCell` replaces `cell` on mobile, for example to drop styling that does not fit the list.
- `align: "end"` right-aligns the desktop header and cells.

## Accessibility

- With a `title`, the section is labelled by its heading and exposed as a region.
- On desktop the data is a real table with column headers; an empty state is a single cell that spans every column.
- On mobile the rows are list items in a `ul`.

`TableList` takes `rows` and a `columns` definition, and renders each row as a `TableListRow` inside one rounded group. Each column has a `slot` that decides where its cell goes: the row title, the description line, the trailing side, or nowhere.

The row parts are also exported, so you can build the same grouped look inside a `FlatList` for long or virtualized lists.

## Usage

<Code lang="tsx" code={"import { TableListTitle, TableListHeader, TableListFooter, TableListSeparator, TableListRow, TableList } from \"@/components/patterns/table-list\""} />

<Code lang="tsx" code={"<View className=\"gap-8\">\n  <TableList\n    title=\"Invoices\"\n    rows={invoices}\n    columns={columns}\n    getKey={(row) => row.id}\n    onRowPress={() => {}}\n  />\n  <TableList rows={[]} columns={columns} emptyText=\"No invoices yet.\" />\n</View>"} />

Define columns with `key`, `header`, `cell` and `slot`. Several `description` columns are joined with ` · `, and several `trailing` columns are shown side by side. Use `mobileCell` to render a different value than `cell` in the list, such as a shorter date.

Pass `onRowPress` to make rows pressable. When there are no rows, `emptyText` is shown in the group. The `TableListColumn` type is exported.

With a `FlatList`, use `TableListRow` as the item, pass `first` and `last` to round the ends, `TableListSeparator` as `ItemSeparatorComponent`, and `TableListHeader` and `TableListFooter` around the list.

## Accessibility

- The group has the `list` role; rows have the `listitem` role, or `button` when `onRowPress` is set.
- `TableListTitle` and `TableListHeader` have the `heading` role.
- Separators are hidden from screen readers.

## Notes

- Rows use `bg-surface-secondary` and `bg-surface-tertiary` when pressed.
- The `header` and `align` column fields are not rendered by the list layout.
