Dialog wraps the dialog primitive of the chosen base. The `Dialog` root manages the open state, and `DialogTrigger` opens it. `DialogContent` renders the window in a portal over a dimmed `DialogOverlay`, with a close button in the top corner by default. Inside it, `DialogHeader` holds the `DialogTitle` and `DialogDescription`, and `DialogFooter` holds the actions. `DialogClose` closes the dialog from any element.

Use a dialog for a short, focused task such as editing a few fields. To confirm a destructive or important action that needs an explicit response, consider an alert dialog. For larger content that slides in from an edge, use a sheet or drawer.

## Installation

### CLI

```bash title="Terminal"
npx shadcn@latest add @esuiss/dialog
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the suiss/ui CLI:

```bash title="Terminal"
npx @esuiss/ui@latest add dialog
```

### Manual

1. Install the dependencies and add the [`cn` helper](/docs/installation#the-cn-helper):

```bash title="Terminal"
npm install @base-ui/react @phosphor-icons/react
```

2. Add the pieces it builds on: [Button](/docs/components/button), `use-scrollbar-gap`.

3. Copy the source into `components/ui/dialog.tsx`:

<ComponentSource path="components/ui/dialog.tsx" />

4. Update the import paths to match your project.

## Usage

```tsx
import { Dialog, DialogTrigger, DialogPortal, DialogClose, DialogOverlay, DialogContent, DialogHeader, DialogFooter, DialogTitle, DialogDescription } from "@/components/ui/dialog"
```

<OnlyBase base="aria">

The dialog is uncontrolled by default; set `defaultOpen` to start open, or control it with `isOpen` and `onOpenChange`. The first pressable child of `Dialog`, such as a `Button`, opens it. Give a `Button` `slot="close"` for a Cancel button.

</OnlyBase>

Set `showCloseButton={false}` on `DialogContent` to remove the corner close button, and set `closeLabel` to replace its icon with a text label. Set `showCloseButton` on `DialogFooter` to add a secondary Close button to the actions. The footer stacks its actions in reverse order on small screens and aligns them to the end on wider screens.

## Accessibility

- The window has the `dialog` role. `DialogTitle` provides its accessible name and `DialogDescription` its accessible description.
- Opening the dialog moves focus inside it. Escape closes it and returns focus to the trigger.
- The icon-only close button has a visually hidden `Close` label.
- Always include a `DialogTitle`; hide it visually with `sr-only` if the design has no visible title.

## Notes

- Styling hooks: `data-slot` values `dialog-overlay`, `dialog-content`, `dialog-close`, `dialog-header`, `dialog-footer`, `dialog-title` and `dialog-description`.
- `data-open` and `data-closed` drive the fade and zoom animation.
- The window is `sm:max-w-md` by default; override it with `className` on `DialogContent`.
- When a close button is shown, the first child of the content gets extra end padding so it does not run under the button.
- Uses the `popover`, `secondary` and `muted-foreground` colors, with a `bg-black/50` backdrop.

Use it for short forms and information that the user can dismiss freely. When the user must make an explicit choice, use Alert Dialog instead.

## Usage

```tsx
import { DialogOverlay, DialogContent, DialogHeader, DialogFooter, DialogTitle, DialogDescription } from "@/components/ui/dialog"
```

```tsx
<View className="items-start">
  <Dialog defaultOpen>
    <DialogTrigger render={<Button variant="outline" />}>
      <Text>Edit profile</Text>
    </DialogTrigger>
    <EditProfileContent />
  </Dialog>
</View>
```

Compose `DialogTrigger` and `DialogContent` with a `DialogHeader` (`DialogTitle`, `DialogDescription`), your content, and a `DialogFooter`. Footer buttons stack vertically with the first child at the bottom, and sit in a row aligned to the end on wider screens. Use `DialogClose` with `render` to turn any `Button` into a close button.

Set `showCloseButton={false}` on the content to hide the corner button, or pass `closeLabel` to show a text button such as "Done" instead of the icon. The header adds end padding so the title does not run under it. `DialogFooter` takes `showCloseButton` to append a secondary Close button.

Use `open` and `onOpenChange` for controlled state, or `defaultOpen` for uncontrolled.

## Accessibility

- The popup has the `dialog` role, is labelled by the title and is marked as modal for VoiceOver.
- Focus moves to the title when the dialog opens.
- The Android back button and the VoiceOver escape gesture close it.
- The icon close button is labelled "Close".

## Notes

- On iOS the content is wrapped in a full-window overlay so it appears above native navigation.
- Animations respect the system Reduce Motion setting.
- Uses `bg-popover`, `bg-black/50` and `bg-secondary` tokens; light and dark follow the system appearance.
