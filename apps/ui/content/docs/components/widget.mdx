`Widget` is a rounded `surface-secondary` card that comes in four sizes: `small` (168 × 168), `medium` (352 × 168), `large` (352 × 352) and `extra-large` (720 × 352), or `auto` to fill its parent. Compose it from `WidgetHeader`, which holds a `WidgetIcon`, `WidgetTitle` and an optional `WidgetAction`, followed by `WidgetValue`, `WidgetDescription`, `WidgetContent` and a `WidgetFooter` pinned to the bottom.

With `resizable`, a corner handle lets people drag the widget to another size. While dragging, a dashed outline previews the size it will snap to on release. Use widgets for glanceable summaries on a dashboard; for general grouped content, use `Card`.

Use `size` with `onSizeChange` to control the size, or `defaultSize` to set where an uncontrolled widget starts. Without either, a resizable widget starts `small` and a fixed widget is `auto`. Limit the sizes a drag can snap to with `sizes`.

Set `resizable="free"` to follow the pointer without snapping; the widget stays between the smallest size and the largest allowed size. Double-click the handle to return to the starting size.

Adapt the content to the current size with the `group/widget` group and `data-size`, for example `group-data-[size=small]/widget:hidden`.

## Accessibility

- `WidgetIcon` is hidden from assistive technologies, so make sure the title conveys its meaning.
- The resize handle is hidden from assistive technologies and works with a pointer only. Offer another way to change the size, such as a control that sets `size`, if it matters.

## Notes

- `Widget` sets `data-size` and `data-align`, and `data-resizing` while dragging. It's also a `@container/widget` container for container queries.
- Parts carry `data-slot` attributes such as `widget`, `widget-container`, `widget-handle`, `widget-preview` and `widget-header`.
- The handle is visible on hover and always visible on touch screens. It mirrors in right-to-left layouts.
- Size changes animate over `500ms`, and the animation is removed when reduced motion is preferred.

`Widget` is a `View` with a rounded, filled surface. It comes in four fixed sizes, `small` (168×168), `medium` (352×168), `large` (352×352) and `extra-large` (720×352), or `auto`, which fills its parent. Fixed sizes animate with Reanimated when the size changes.

With `resizable`, a corner handle lets the user drag the widget between sizes: a dashed outline previews the size it will snap to, a selection haptic plays on each new snap, and double-tapping the handle returns to the initial size. Only sizes that fit the available width are offered. Set `align="center"` to center the content, which also hides `WidgetAction`.

## Usage

<Code lang="tsx" code={"import { Widget, WidgetHeader, WidgetIcon, WidgetTitle, WidgetAction, WidgetDescription, WidgetValue, WidgetContent, WidgetFooter } from \"@/components/ui/widget\""} />

<Code lang="tsx" code={"<Widget size=\"small\" align=\"start\">\n  <Weather />\n</Widget>"} />

Compose the content from `WidgetHeader` (with `WidgetIcon`, `WidgetTitle` and `WidgetAction`), then `WidgetValue`, `WidgetDescription` or `WidgetContent`, and `WidgetFooter`, which sticks to the bottom. Plain strings passed to `WidgetContent` and `WidgetFooter` are wrapped in `Text`.

The size is uncontrolled with `defaultSize`, or controlled with `size` and `onSizeChange`. Use `sizes` to limit which sizes the user can pick. A non-resizable widget defaults to `auto`; a resizable one defaults to `small`.

`useWidget` returns the current `size` and `align` so custom content can adapt to the widget size.

## Accessibility

- The resize handle has the `adjustable` role, its `resizeLabel` and the current size as its value; increment and decrement actions step through the available sizes, so VoiceOver and TalkBack users can resize without dragging.
- `WidgetTitle` has the `heading` role.
- `WidgetIcon` and the resize preview outline are hidden from assistive technology.
- Size animations respect the system reduce motion setting.

## Notes

- Uses `bg-surface-secondary` for the surface, `bg-control` for icon frames, and `text-label-quaternary` for the handle, which turns `text-accent` while dragging.
- The handle and drag direction mirror in right-to-left layouts.
- Light and dark colors follow the system appearance.
