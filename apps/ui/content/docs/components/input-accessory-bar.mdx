`InputAccessoryBar` connects a set of inputs and shows a bar above the keyboard while one of them is focused. The up and down arrows move focus to the previous or next input, and the done button dismisses the keyboard.

On iOS the bar is a native `InputAccessoryView`, attached to the keyboard. On Android it is rendered through a portal and positioned just above the keyboard while an input is focused.

## Usage

<Code lang="tsx" code={"import { InputAccessoryBar, InputAccessoryBarInput } from \"@/components/ui/input-accessory-bar\""} />

<Code lang="tsx" code={"<InputAccessoryBar>\n  <Form />\n</InputAccessoryBar>"} />

Wrap the form in `InputAccessoryBar` and use `InputAccessoryBarInput` in place of `Input`. Inputs are ordered by the order they mount. The return key reads "next" on every input but the last, which reads "done" and dismisses the keyboard.

For other text inputs, such as a `Textarea`, call `useInputAccessoryBarInput()` and spread the returned props onto the input. Inside a Keyboard Scroll View, the focused input is scrolled into view.

Use `previousLabel`, `nextLabel` and `doneLabel` to localize the buttons, and `onDone` to react when done is pressed.

## Accessibility

- The arrow buttons are labelled with `previousLabel` and `nextLabel` and are disabled at the first and last input.
- The done button is a text button that dismisses the keyboard.

## Notes

- iOS uses the native input accessory view; Android uses a portal and reserves the bar height so keyboard-aware layouts stay above it.
- Uses `bg-surface-raised` (a secondary surface in dark mode) and `border-separator` tokens.
