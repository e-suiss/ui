`Checkbox` wraps the checkbox primitive and renders a check icon inside its indicator when checked. It is a single self-contained part: there are no child components to compose.

Use a checkbox for independent options that people can select in any combination, such as accepting terms or opting in to email. For a mutually exclusive choice, use a radio group; for a setting that takes effect immediately, consider a switch.

## Installation

### CLI

```bash title="Terminal"
npx shadcn@latest add @esuiss/checkbox
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

```bash title="Terminal"
npx @esuiss/ui@latest add checkbox
```

### Manual

1. Install the dependencies and add the [`cn` helper](/docs/installation#the-cn-helper):

```bash title="Terminal"
npm install @base-ui/react @phosphor-icons/react
```

2. Copy the source into `components/ui/checkbox.tsx`:

<ComponentSource path="components/ui/checkbox.tsx" />

3. Update the import paths to match your project.

## Usage

```tsx
import { Checkbox } from "@/components/ui/checkbox"
```

```tsx
<Checkbox aria-label="Accept terms" />
```

Leave the checkbox uncontrolled with `defaultChecked`, or control it with `checked` and `onCheckedChange`. Pair it with a visible `Label`: wrapping the checkbox in `Label` makes the whole label text clickable. To add supporting text, give the checkbox an `id` and an `aria-describedby` that points to the description element.

## Accessibility

- Renders with the `checkbox` role and exposes its checked state to assistive technology.
- Toggles on click and with Space when focused.
- Needs an accessible name: wrap it in a `Label`, associate a `Label` through `htmlFor` and `id`, or set `aria-label`.
- When `disabled`, it sets `aria-disabled`, ignores clicks, and is removed from the Tab order.
- Set `aria-invalid` to communicate a validation error; the border turns to the `destructive` color.

## Notes

- Styling hooks: `data-slot="checkbox"` on the root and `data-slot="checkbox-indicator"` on the indicator.
- State attributes set by the primitive drive the checked and disabled styles.
- Uses the `primary`, `primary-foreground`, `background` and `border` colors, and `opacity-50` when disabled.
- The hit area extends beyond the visible box through an `after` pseudo-element, making the small control easier to tap.

## Usage

```tsx
import { Checkbox } from "@/components/ui/checkbox"
```

```tsx
<CheckboxDemo />
```

Use `checked` with `onCheckedChange` for controlled state, or `defaultChecked` for uncontrolled. Set `indeterminate` for a parent checkbox whose children are partly selected.

Pair the checkbox with a `Label`: give the label a `nativeID` and the checkbox a matching `accessibilityLabelledBy`, and toggle the value from the label's `onPress`. Set `invalid` to show a destructive border.

## Accessibility

- Has the `checkbox` role with `checked` (or `mixed` when indeterminate) and `disabled` state.
- Link it to a visible label with `accessibilityLabelledBy`, or give it an `accessibilityLabel`.

## Notes

- Uses `bg-primary` when checked and `bg-background` with a translucent border when unchecked; in dark mode the unchecked box is filled instead of outlined.
- Light and dark follow the system appearance.
