`Tabs` wraps the Base UI Tabs primitive. `TabsList` holds the `TabsTrigger` buttons, and each `TabsContent` panel is shown when its `value` matches the selected tab. An indicator slides to the active tab: a raised pill in the `default` variant, or an underline in the `line` variant.

When there are more tabs than fit, the list scrolls horizontally and keeps the active tab in view. On small screens, a horizontal list bleeds to the edges of its scroll container. Use `Tabs` to switch views within a page. For app-level navigation, use `TabBar` or `Sidebar`; for a compact single-choice control, consider a segmented `ToggleGroup`.

## Usage

```tsx
import { Tabs, TabsList, TabsTrigger, TabsContent } from "@/components/ui/tabs"
```

```tsx
<Tabs defaultValue="account" orientation="horizontal">
  <TabsList variant="default">
    {tabs.map((tab) => (
      <TabsTrigger key={tab.value} value={tab.value}>
        {tab.label}
      </TabsTrigger>
    ))}
  </TabsList>
  {tabs.map((tab) => (
    <TabsContent
      key={tab.value}
      value={tab.value}
      className="text-muted-foreground"
    >
      {tab.content}
    </TabsContent>
  ))}
</Tabs>
```

Use `defaultValue` on `Tabs` for an uncontrolled set, or `value` with `onValueChange` to control it. Give each `TabsTrigger` and its `TabsContent` the same `value`. Set `orientation="vertical"` on `Tabs` to stack the triggers beside the panel.

## Accessibility

- The list has the `tablist` role with `aria-orientation`; triggers are `tab` elements with `aria-selected`, and panels are `tabpanel` elements.
- Arrow keys move focus between tabs, wrapping at the ends; `Enter` or `Space` selects the focused tab. Vertical tabs use the up and down arrow keys.
- `Home` and `End` move focus to the first and last tabs.
- Disabled tabs set `aria-disabled` and can't be selected by click or keyboard.

## Notes

- Parts carry `data-slot` attributes: `tabs`, `tabs-list`, `tabs-list-content`, `tabs-indicator`, `tabs-trigger` and `tabs-content`. The list and indicator set `data-variant`, and the active trigger sets `data-active`.
- The edge bleed on small screens is set through the `--tabs-list-bleed-start` and `--tabs-list-bleed-end` properties, which the list measures itself.
- `className` on `TabsList` styles the inner `tabs-list-content` element, not the scrolling list.
- Indicator and scroll animations are removed when reduced motion is preferred.

`Tabs` groups a `TabsList` of `TabsTrigger` buttons with matching `TabsContent` panels. The active tab is marked by an indicator that slides between tabs with a Reanimated layout transition.

`TabsList` has two variants: `default`, a segmented control with a raised indicator on a filled track, and `line`, a transparent list with a thin underline. Both work in horizontal and vertical orientation.

## Usage

```tsx
import { Tabs, TabsList, TabsTrigger, TabsContent } from "@/components/ui/tabs"
```

```tsx
<TabsDemo />
```

Give each `TabsTrigger` and its `TabsContent` the same `value`. Use `defaultValue` for an uncontrolled tab set, or `value` with `onValueChange` to control it.

Set `orientation="vertical"` on `Tabs` to stack the list beside the panels. Put an `Icon` next to the `Text` in a trigger for icon tabs.

Inactive panels are unmounted unless you set `keepMounted` on `TabsContent`. `tabsListVariants` is exported for reuse.

## Accessibility

- `TabsList` has the `tablist` role and each trigger has the `tab` role.
- Triggers report `selected` and `disabled` in their accessibility state, so VoiceOver and TalkBack announce the current tab.
- Hidden panels kept with `keepMounted` are removed from the accessibility tree.
- The indicator animation follows the system reduce motion setting.

## Notes

- The `default` track uses `bg-control` with a `bg-surface-raised` indicator (`bg-label-quaternary` in dark mode); the `line` indicator uses `bg-label`.
- Labels use `text-label` when active, `text-label-secondary` when inactive and `text-label-quaternary` when disabled.
- Light and dark colors follow the system appearance.
