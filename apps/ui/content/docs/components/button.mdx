`Button` renders a native `button` by default. It supports eight visual variants, five text sizes and five icon-only sizes, and an optional `block` mode that fills the container width.

Use the `default` variant for the primary action in a view, `secondary`, `tinted` or `outline` for supporting actions, `ghost` and `plain` for low-emphasis actions, and `destructive` for actions that delete or remove. To join several buttons into one control, use Button Group.

## Installation

### CLI

```bash title="Terminal"
npx shadcn@latest add @esuiss/button
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

```bash title="Terminal"
npx @esuiss/ui@latest add button
```

### Manual

1. Install the dependencies and add the [`cn` helper](/docs/installation#the-cn-helper):

```bash title="Terminal"
npm install @base-ui/react class-variance-authority
```

2. Copy the source into `components/ui/button.tsx`:

<ComponentSource path="components/ui/button.tsx" />

3. Update the import paths to match your project.

## Usage

```tsx
import { Button } from "@/components/ui/button"
```

```tsx
<Button>Button</Button>
```

Mark icons with `data-icon="inline-start"` or `data-icon="inline-end"` to tighten the padding on that side. Icons without a size class are sized automatically.

Use an `icon` size, such as `icon` or `icon-sm`, for buttons that contain only an icon, and give them an `aria-label`.

<OnlyBase base="base">

To render a link or a router component with button styling, use the `render` prop from Base UI. `buttonVariants` is also exported if you need the classes on another element.

</OnlyBase>

<OnlyBase base="radix">

To render a link or a router component with button styling, set `asChild` and pass it as the child. `buttonVariants` is also exported if you need the classes on another element.

</OnlyBase>

<OnlyBase base="aria">

`Button` always renders a `button`. To give a link or a router component button styling, apply the classes from `buttonVariants` to it.

</OnlyBase>

### Button

The interactive button element.

| --- | --- | --- | --- |
| `variant` | `"default" \| "outline" \| "secondary" \| "tinted" \| "ghost" \| "plain" \| "destructive" \| "link"` | `"default"` | Visual style: `default`, `outline`, `secondary`, `tinted`, `ghost`, `plain`, `destructive` or `link`. |

## Accessibility

- Renders a native `button`, so `Enter` and `Space` activate it.
- A disabled button is removed from the tab order.
- Icon-only buttons need an `aria-label`.
- Keyboard focus shows a 3px ring in `--ring`; the `destructive` variant tints it with `ring-destructive/20`.
- `aria-invalid` adds a destructive border and ring, and `aria-expanded` shows a selected background on `outline`, `ghost` and `plain` buttons that open menus or popovers.

## Notes

- Styling hook: `data-slot="button"`.
- Colors come from the `primary`, `secondary`, `accent` and `destructive` variables. Hover uses the same color with an opacity, such as `hover:bg-primary/80`, and disabled buttons use `opacity-50`.
- Buttons in a group raise the focused one above its neighbors so the whole ring stays visible.

## Accessibility

- Renders a `Pressable` with `role="button"`, so VoiceOver and TalkBack announce it as a button.
- `disabled` is announced and blocks presses.
- Icon-only buttons need an `accessibilityLabel`.

## Notes

- Colors come from semantic tokens such as `bg-primary`, `bg-secondary`, `bg-primary/10 dark:bg-primary/20` and `bg-destructive/10 dark:bg-destructive/20`, with `opacity-80` while pressed and `opacity-50` when disabled.
- Light and dark colors follow the system appearance.
