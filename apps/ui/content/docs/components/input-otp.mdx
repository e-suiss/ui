Input OTP is built on the `input-otp` library. `InputOTP` renders a single hidden text input that holds the whole code, and displays it through `InputOTPSlot` elements, each showing the character at its `index`. Group slots with `InputOTPGroup`, and place an `InputOTPSeparator` between groups to split a code, for example into two sets of three.

Use it for verification and two-factor codes. For other short values, use `Input`.

```bash title="Terminal"
npx shadcn@latest add @esuiss/input-otp
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

## Usage

```tsx
import { InputOTP, InputOTPGroup, InputOTPSlot, InputOTPSeparator } from "@/components/ui/input-otp"
```

```tsx
<InputOTP maxLength={6} aria-label="Verification code">
  <InputOTPGroup>
    <InputOTPSlot index={0} />
    <InputOTPSlot index={1} />
    <InputOTPSlot index={2} />
  </InputOTPGroup>
  <InputOTPSeparator />
  <InputOTPGroup>
    <InputOTPSlot index={3} />
    <InputOTPSlot index={4} />
    <InputOTPSlot index={5} />
  </InputOTPGroup>
</InputOTP>
```

Set `maxLength` to the length of the code and render one `InputOTPSlot` for each position, with `index` values from `0`. The value is uncontrolled with `defaultValue`, or controlled with `value` and `onChange`, which receives the code as a string. Restrict accepted characters with `pattern`, for example with `REGEXP_ONLY_DIGITS_AND_CHARS` from `input-otp`.

Typing fills the slots in order and stops at `maxLength`; Backspace removes the last character. Set `aria-invalid` on `InputOTP` to show the error style on every slot.

## Accessibility

- The code is entered into one native text input, so it has the `textbox` role. Give it an accessible name with `aria-label` or an associated label.
- Slots are visual only; assistive technology reads the value of the input.
- `InputOTPSeparator` has the `separator` role.
- When `disabled`, the input cannot be edited and the slots are dimmed.

## Notes

- Styling hooks: `data-slot` values `input-otp`, `input-otp-group`, `input-otp-slot` and `input-otp-separator`. The active slot gets `data-active="true"` and a `primary` border.
- Slots react to the invalid and disabled states of the input through the `data-input-otp-container` attribute on its container.
- The blinking caret uses the `animate-caret-blink` animation.
- Uses the `secondary`, `primary` and `destructive` colors, and `opacity-50` when disabled.

`InputOTP` is backed by one hidden `TextInput` and shows each character in an `InputOTPSlot`. The active slot gets a `border-primary` border and a blinking caret. The hidden input uses the one-time-code autofill hints, so codes from messages can be filled in automatically, and pasting fills every slot.

Group slots with `InputOTPGroup` and place an `InputOTPSeparator` between groups for codes such as `123-456`.

<Only platform="rn">

Set `length` and render one `InputOTPSlot` per `index`. Use `value` with `onValueChange` for controlled state, or `defaultValue`. `onValueComplete` fires when every slot is filled.

`validationType` limits input to `numeric` (the default number pad), `alpha`, `alphanumeric` or `none`, and `onValueInvalid` reports rejected characters. Set `mask` to hide the characters.

Use `InputOTPSlotClassContext` to style every slot at once, or `className` on a single slot.

</Only>

## Accessibility

- Screen readers interact with the hidden input, labelled "N character code" by default; pass `inputProps` with an `accessibilityLabel` to localize it.
- The visual slots are hidden from VoiceOver and TalkBack.
- `disabled` is exposed on the input.

## Notes

- The hidden input sets `textContentType="oneTimeCode"` for iOS and `autoComplete="one-time-code"` for Android autofill.
- The caret blink respects the system Reduce Motion setting.
- Uses `bg-secondary`, `border-primary` and `bg-primary` tokens; light and dark follow the system appearance.
