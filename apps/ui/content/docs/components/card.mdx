A `Card` stacks a `CardHeader`, `CardContent` and `CardFooter` with consistent spacing. The header holds a `CardTitle`, an optional `CardDescription`, and an optional `CardAction` that sits in the top-end corner. An `img` placed as the first child runs edge to edge, with rounded top corners and no top padding.

Use a card to present a self-contained summary, such as a plan, a metric or a place. For dense lists of rows, use Item or a table instead.

All parts are plain `div` elements, so you can omit any of them. Add `border-b` to `CardHeader` or `border-t` to `CardFooter` to draw a divider; the card adds matching padding on that side.

Spacing is controlled by the `--card-spacing` custom property, which the `sm` size reduces.

## Accessibility

- Card parts are non-semantic `div` elements, and `CardTitle` is not a heading. If the title belongs in the document outline, place a heading element such as `h2` inside it.
- Icon-only buttons in `CardAction` need an `aria-label`.

## Notes

- Styling hooks: `data-slot` values `card`, `card-header`, `card-title`, `card-description`, `card-action`, `card-content` and `card-footer`, plus `data-size` and `data-variant` on the root.
- The header switches to a two-column grid when it contains a `CardAction`.
- Calendar detects `data-slot="card-content"` and drops its own background inside a card.
