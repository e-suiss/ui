`Questionnaire` renders a `form` that presents a sequence of questions, one at a time. Each `QuestionnaireItem` is a `fieldset` with a `QuestionnaireTitle`, an optional `QuestionnaireDescription`, an answer area and a `QuestionnaireError`. Answers are either `QuestionnaireChoices` holding `QuestionnaireChoice` cards (with optional `QuestionnaireChoiceDescription`), or a `QuestionnaireInput`.

`QuestionnaireProgress` shows the current position, and `QuestionnaireActions` lays out `QuestionnairePrevious`, `QuestionnaireSkip`, `QuestionnaireNext` and `QuestionnaireSubmit`, which show and hide themselves based on the current question. Use Questionnaire for onboarding flows and surveys; use Field and regular form controls when all fields should be visible at once.

Give every item a unique `name`; answers are submitted as form data under that name. The first item is shown by default. Use `defaultItem` to start elsewhere, or `item` with `onItemChange` to control the active question.

A `required` item blocks Next and Submit until it is answered. An optional item shows the Skip button. Set `multiple` on an item to render its choices as checkboxes instead of radio buttons.

Pass `items` to define the sequence, which items are required or disabled, and the order used for shortcut keys, instead of deriving them from the rendered items. Native browser validation is off by default (`noValidate`); the component runs its own validation on Next and Submit.

## Accessibility

- Each item is a `fieldset` named by its `legend` title; inactive items are `hidden` and `inert`.
- Choices are native radio buttons or checkboxes inside a `label`. A choice description is linked with `aria-describedby`.
- `QuestionnaireInput` is labelled by the question title unless you pass `aria-label`.
- The item's description and, when invalid, its error are linked with `aria-describedby`. The error uses `role="alert"` and focus moves to the invalid answer.
- `QuestionnaireProgress` has `role="progressbar"`, an `aria-label` of `Questionnaire progress`, `aria-valuetext` and `aria-live="polite"`.
- Keyboard: Enter on an answered control advances or submits; Command or Control plus Enter advances from anywhere; ArrowUp and ArrowDown move between answers; outside text fields and radio buttons, ArrowLeft goes back and ArrowRight goes forward once the question has an answer. The active item lists these in `aria-keyshortcuts`.
- Hidden navigation buttons are `aria-hidden`, `inert` and removed from the tab order.

## Notes

- Styling hooks: every part sets a `data-slot`, such as `questionnaire`, `questionnaire-item`, `questionnaire-choice`, `questionnaire-choice-indicator`, `questionnaire-choice-shortcut`, `questionnaire-input` and `questionnaire-error`.
- Choices expose `data-checked` or `data-unchecked`, plus `data-type`, `data-disabled`, `data-invalid` and `data-shortcut`. Inputs expose `data-filled` or `data-empty`. Navigation buttons expose `data-visible` or `data-hidden`.
- Shortcut badges are hidden below the `md` breakpoint.
- The default error text is `Choose an answer to continue.` for required items; pass children to customize it.
- Uses the `accent`, `separator`, `control`, `danger` and `item-hover` tokens.

`Questionnaire` is a `View` that tracks which question is active, collects answers and validates them. Each `QuestionnaireItem` is one question; only the active item is shown, and moving between items slides the content horizontally with a Reanimated keyframe that follows the layout direction.

Items hold `QuestionnaireChoice` rows, which are `Pressable` radios or, with `multiple`, checkboxes, or a `QuestionnaireInput` for a typed answer. `QuestionnaireActions` holds the Previous, Skip, Next and Submit buttons, each of which only appears when it applies.

## Usage

<Code lang="tsx" code={"import { Questionnaire, QuestionnaireProgress, QuestionnaireItem, QuestionnaireTitle, QuestionnaireDescription, QuestionnaireChoices, QuestionnaireChoice, QuestionnaireChoiceDescription, QuestionnaireInput, QuestionnaireError, QuestionnaireActions, QuestionnairePrevious, QuestionnaireSkip, QuestionnaireNext, QuestionnaireSubmit } from \"@/components/ui/questionnaire\""} />

<Code lang="tsx" code={"<Onboarding />"} />

Give every `QuestionnaireItem` a unique `name`; answers are collected under that name. Mark items `required` to block moving on without an answer; optional items show the Skip button. `QuestionnaireError` appears only when the item is invalid and has a default message you can replace.

The active item is uncontrolled through `defaultItem` or controlled with `item` and `onItemChange`. `onSubmit` receives the collected values: a string for single-answer items and a string array for `multiple` items.

`QuestionnaireChoice` supports `defaultChecked`, or controlled `checked` with `onCheckedChange`. `QuestionnaireInput` takes a `type` that sets the keyboard, autocomplete and secure entry. `QuestionnaireProgress` shows "Question 1 of 3" by default and accepts a render function. Use `useQuestionnaireContext` to build custom controls, or `useQuestionnaire` for the underlying state.

## Accessibility

- Each item has the `radiogroup` role, or `group` when `multiple`, and is labelled by its `QuestionnaireTitle`, which has the `heading` role.
- Choices have the `radio` or `checkbox` role with checked and disabled states.
- `QuestionnaireInput` is labelled by the title unless you pass an `accessibilityLabel`.
- `QuestionnaireProgress` has the `progressbar` role, a value such as "Question 2 of 3" and a polite live region.
- `QuestionnaireError` has the `alert` role with a polite live region.
- Slide transitions respect the system reduce motion setting.

## Notes

- Selecting a choice plays a selection haptic.
- Selected choices use `border-accent` and `bg-accent`; invalid items use `border-danger`.
- The slide direction flips for right-to-left layouts.
- Light and dark colors follow the system appearance.
