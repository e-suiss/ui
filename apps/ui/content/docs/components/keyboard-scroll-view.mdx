`KeyboardScrollView` wraps the React Native `ScrollView`. When the keyboard opens, it measures how much of the view the keyboard covers, adds matching space at the end of the content and scroll indicator, and scrolls just enough to bring the focused input above the keyboard.

Use it for forms and other screens with text fields that would otherwise end up behind the keyboard.

## Usage

```tsx
import { KeyboardScrollView } from "@/components/ui/keyboard-scroll-view"
```

```tsx
<KeyboardScrollView className="-m-4" contentContainerClassName="gap-4 p-4">
  <Text variant="h3">Shipping address</Text>
  <Fields />
</KeyboardScrollView>
```

Place inputs anywhere inside the view; no extra setup is needed. Set `bottomOffset` to leave more space between the focused field and the keyboard.

All `ScrollView` props are passed through. By default taps on the content are handled while the keyboard is open (`keyboardShouldPersistTaps="handled"`), and dragging dismisses the keyboard.

`KeyboardScrollViewContext` exposes `scrollToFocused`, which children can call to bring the focused input into view again, for example after their layout changes.

## API Reference

<ApiPart index={1}>

### KeyboardScrollView

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `bottomOffset` | `number` | `16` | Space kept between the focused input and the keyboard. Defaults to `16`. |

Also accepts the props of `ScrollViewProps`, `React.RefAttributes<ScrollView>`.

</ApiPart>

## Accessibility

- The view is a standard `ScrollView`, so screen reader scrolling works as usual.

## Notes

- `keyboardDismissMode` defaults to `interactive` on iOS and `on-drag` on Android.
- After a touch while the keyboard is open, the view checks the focused input again after a short delay.
- The view fills its parent with `flex-1`.
- Only an input that is inside the visible frame of the scroll view is adjusted; inputs scrolled out of view are left alone.
