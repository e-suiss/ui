A `Field` wraps one control together with its `FieldLabel`, an optional `FieldDescription` and an optional `FieldError`. It automatically adds the ids of its descriptions and errors to the control's `aria-describedby`, so supporting text is announced with the control. Use `FieldContent` to stack a label and description beside a control in a horizontal field, and `FieldTitle` for a non-label heading inside a field.

`FieldGroup` stacks fields with consistent spacing, and its `inset` variant groups them into a rounded list, like iOS Settings. `FieldSet` and `FieldLegend` group related fields under a caption, and `FieldSeparator` divides sections, optionally with text. Use these parts with any control in the library, such as `Input`, `Textarea`, `Checkbox`, `Switch` or `RadioGroup`.

## Usage

<Code lang="tsx" code={"import { FieldSet, FieldLegend, FieldGroup, Field, FieldContent, FieldLabel, FieldTitle, FieldDescription, FieldSeparator, FieldError } from \"@/components/ui/field\""} />

<Code lang="tsx" code={"<div className=\"w-96\">\n  <Field orientation=\"vertical\">\n    <FieldLabel htmlFor=\"field-username\">Username</FieldLabel>\n    <Input id=\"field-username\" placeholder=\"janedoe\" />\n    <FieldDescription>\n      Choose a unique name for your account.\n    </FieldDescription>\n  </Field>\n</div>"} />

Connect each `FieldLabel` to its control with `htmlFor` and `id`. Set `orientation="horizontal"` to place the label beside the control, for example for a checkbox or switch, or `responsive` to switch from vertical to horizontal when the surrounding `FieldGroup` is wide enough.

To show an error, set `aria-invalid` on the control and render a `FieldError` with children or an `errors` array. Pass `data-disabled` on a `Field` to dim its label when the control is disabled.

To build selectable cards, place a horizontal `Field` inside a `FieldLabel`; the label gets a border, and a highlighted ring when the control inside it is checked.

## Accessibility

- `Field` has the `group` role and links its descriptions and errors to its first control through `aria-describedby`, updating the link when they change.
- `FieldSet` renders a native `fieldset`, which takes its accessible name from `FieldLegend`.
- `FieldError` has the `alert` role, so assistive technology announces it when it appears. It renders nothing when it has no children and no errors.
- Set `aria-invalid` on the control to mark it invalid; `FieldError` does not set it for you.
- Clicking a `FieldLabel` focuses or toggles its associated control.

## Notes

- Styling hooks: `data-slot` values `field-set`, `field-legend`, `field-group`, `field`, `field-content`, `field-label` (used by both `FieldLabel` and `FieldTitle`), `field-description`, `field-separator` and `field-error`.
- `Field` sets `data-orientation`, and `FieldGroup` and `FieldLegend` set `data-variant`.
- `FieldGroup` is a container query context named `field-group`, which drives the `responsive` orientation.
- Uses the `surface-secondary`, `separator`, `label-secondary`, `link`, `danger`, `accent` and `item-hover` tokens.

`Field` wraps one control, such as an `Input`, `Textarea` or `Switch`, with a `FieldLabel`, an optional `FieldDescription` and a `FieldError`. It shares the field's disabled and invalid state with the control and handles validation: required values, length limits and custom `validate` functions, checked on submit, blur or change.

`FieldSet` and `FieldLegend` group related fields under a heading, and `FieldGroup` stacks fields. The `inset` variant of `FieldGroup` turns the fields into rows on a rounded secondary surface with hairlines between them, like a settings list.

## Usage

<Code lang="tsx" code={"import { FieldSet, FieldLegend, FieldGroup, Field, FieldContent, FieldLabel, FieldTitle, FieldDescription, FieldSeparator, FieldError } from \"@/components/ui/field\""} />

<Code lang="tsx" code={"<Field>\n  <FieldLabel>Username</FieldLabel>\n  <Input placeholder=\"evilrabbit\" autoCapitalize=\"none\" />\n  <FieldDescription>\n    Choose a unique username for your account.\n  </FieldDescription>\n</Field>"} />

Put a `FieldLabel`, the control and a `FieldError` inside `Field`. The control is labelled by the label and uses the description and error text as its accessibility hint. Set `invalid` to force the error state, or let validation decide it.

`FieldError` shows its children, or the messages from `errors` (for example from a form library), and can be limited to one failure with `match`, such as `tooShort`. Use `orientation="horizontal"` for a label beside a switch or checkbox, with `FieldContent` holding a `FieldTitle` and `FieldDescription`.

`FieldSeparator` divides fields and can show short text such as "or" in the middle.

## Accessibility

- The control is labelled by `FieldLabel` and gets the description and error text as its accessibility hint.
- `FieldError` has the `alert` role, so screen readers announce it when it appears.
- `FieldSet` has the `group` role labelled by its legend; the legend has the `header` role.
- Disabled state is passed to the label and control.

## Notes

- Uses `text-label`, `text-label-secondary`, `text-danger` and `bg-surface-secondary` tokens; light and dark follow the system appearance.
- Inset separators use start and end offsets, so they flip in right-to-left layouts.
