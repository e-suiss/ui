Alert Dialog wraps the Base UI Alert Dialog primitive. An `AlertDialog` root contains an `AlertDialogTrigger` and an `AlertDialogContent`. The content renders its own portal and scrim overlay, and typically holds an `AlertDialogHeader` (with optional `AlertDialogMedia`, plus `AlertDialogTitle` and `AlertDialogDescription`) followed by an `AlertDialogFooter` with `AlertDialogCancel` and `AlertDialogAction` buttons.

Use it when a decision must be made before continuing, such as signing out or deleting data. Unlike a regular dialog, it is not dismissed by clicking outside. For a choice of actions anchored to the bottom of the screen, use Alert Sheet.

`AlertDialogContent` already includes `AlertDialogPortal` and `AlertDialogOverlay`, so you rarely use those parts directly.

`AlertDialogAction` and `AlertDialogCancel` both close the dialog and render a `Button`; pass `variant` and `size` to style them. Cancel defaults to the `secondary` variant and Action to `default`. Use `variant="destructive"` on the action for irreversible operations.

The dialog is uncontrolled by default; use `defaultOpen`, or control it with `open` and `onOpenChange`.

## Accessibility

- The popup has the `alertdialog` role, named by `AlertDialogTitle` and described by `AlertDialogDescription`.
- Opening moves focus into the dialog; closing returns focus to the trigger.
- `Escape` closes the dialog.
- Clicking the overlay does not close it; a choice must be made with a footer button or `Escape`.

## Notes

- Styling hooks: `data-slot` values from `alert-dialog` through `alert-dialog-cancel`; the content also sets `data-size`.
- Surface tokens: `bg-surface-raised` for the dialog, `bg-scrim` for the overlay and `bg-surface-secondary` for media.
- Enter and exit use fade and zoom animations keyed to `data-open` and `data-closed`.

`AlertDialog` is a modal that cannot be dismissed by tapping the scrim. `AlertDialogContent` renders through a portal (inside a full-window overlay on iOS) with a dimmed scrim and a centered card that scales and fades in.

Use it for confirmations that need an explicit choice, such as deleting data. For less critical content that can be dismissed freely, use Dialog; for a list of choices anchored to the bottom of the screen, use Alert Sheet.

## Usage

<Code lang="tsx" code={"import { AlertDialogOverlay, AlertDialogContent, AlertDialogHeader, AlertDialogFooter, AlertDialogMedia, AlertDialogTitle, AlertDialogDescription, AlertDialogAction, AlertDialogCancel } from \"@/components/ui/alert-dialog\""} />

<Code lang="tsx" code={"<View className=\"items-start\">\n  <AlertDialog defaultOpen>\n    <AlertDialogTrigger render={<Button variant=\"outline\" />}>\n      <Text>Show dialog</Text>\n    </AlertDialogTrigger>\n    <AlertDialogBody />\n  </AlertDialog>\n</View>"} />

Compose `AlertDialogTrigger`, then `AlertDialogContent` with an `AlertDialogHeader` (`AlertDialogTitle`, `AlertDialogDescription`) and an `AlertDialogFooter` holding `AlertDialogCancel` and `AlertDialogAction`. Both footer buttons close the dialog and stretch to equal widths inside the footer.

`AlertDialogAction` and `AlertDialogCancel` accept Button's `variant` and `size`; use `variant="destructive"` for destructive confirmations. Add `AlertDialogMedia` above the title for an icon badge.

Use `open` and `onOpenChange` for controlled state, or `defaultOpen` for uncontrolled. Pass `portalHost` to render into a named portal host.

## Accessibility

- The popup has the `alertdialog` role, is labelled by the title and is marked as modal for VoiceOver.
- Focus moves to the title when the dialog opens.
- Tapping the scrim does not close it; the Android back button and the VoiceOver escape gesture do.
- The title has the `heading` role, and the action buttons have the `button` role.

## Notes

- On iOS the content is wrapped in a full-window overlay so it appears above native navigation.
- Enter and exit animations respect the system Reduce Motion setting.
- Uses `bg-surface-raised`, `bg-scrim` and label tokens; light and dark follow the system appearance.
