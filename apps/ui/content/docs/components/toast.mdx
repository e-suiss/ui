Toasts are built on the Base UI Toast primitive. `Toaster` is the ready-made setup: it combines `ToastProvider`, `ToastPortal` and `ToastViewport`, and renders each queued toast as a `Toast` with a `ToastContent` row holding a status icon, `ToastTitle`, `ToastDescription`, `ToastAction` and `ToastClose`.

New toasts stack at the bottom of the screen, with older ones scaled down behind, and expand into a list on hover or focus. A toast's `type` adds a colored icon: `success`, `info`, `warning` or `error`, or a progress ring for `loading`. Use toasts for short confirmations and background results; for messages that need a decision, use `AlertDialog`.

## Usage

```tsx
import { Button } from "@/components/ui/button"
import { Toaster, toast } from "@/components/ui/toast"
```

```tsx
<Toaster>
  <Button
    variant="outline"
    onClick={() =>
      toast.add({
        title: "Event created",
        description: "Friday, October 3 at 9:00 AM",
      })
    }
  >
    Show toast
  </Button>
</Toaster>
```

Render `Toaster` once near the root of your app, wrapping the content that shows toasts. Call `toast.add({ title, description, type })` from anywhere, or read the manager inside the tree with `useToastManager()`. `add` returns an id that you can pass to `close`; `close()` with no id closes every toast.

Pass `actionProps` to show a `ToastAction` button, and `timeout` in milliseconds to change how long a toast stays; `0` keeps it until it's closed. `toast.promise(promise, { loading, success, error })` shows a loading toast that turns into the success or error toast when the promise settles.

`Toaster` uses the shared `toast` manager by default. Pass `toastManager` to use one created with `createToastManager()` instead. Use the individual parts only to build a custom toast list.

## Accessibility

- The viewport is a `region` landmark named `Notifications`.
- Each toast has the `dialog` role, named by its title and described by its description.
- `ToastClose` has the accessible name `Close toast`.
- Prefer an action that can also be reached elsewhere, since toasts dismiss themselves after their timeout.

## Notes

- On small screens the stack is centered at the bottom, inset from the edges and up to `max-w-sm` wide; from the `sm` breakpoint it sits in the bottom end corner, up to `max-w-sm` wide.
- Toasts can be swiped away; the exit animation follows the swipe direction.
- Parts carry `data-slot` attributes such as `toast-viewport`, `toast`, `toast-content`, `toast-icon` and `toast-close`.
- Status icons are solid circles filled with `fill-green-500`, `fill-primary`, `fill-orange-500` and `fill-destructive`, with a white glyph (`text-primary-foreground` on the info icon); the loading ring uses `stroke-primary`. The ring's progress animation is removed when reduced motion is preferred.

Render `Toaster` once near the root, then call the exported `toast` manager from anywhere: `toast.add({ title, description, type })` returns an id, `toast.update(id, updates)` changes a toast, and `toast.close(id)` removes it (or all toasts when called without an id).

`toast.promise(promise, { loading, success, error })` shows a loading toast and replaces it with the success or error state when the promise settles.

Pass `actionProps` (for example `{ children: "Undo", onPress }`) to show an action button. Set `priority: "high"` for urgent messages and `timeout` to override the provider default; `loading` toasts stay until updated.

Use `createToastManager` to create a separate manager and pass it to `Toaster` as `toastManager`, and `useToastManager` to read the current toasts and actions inside the provider. The lower-level parts are exported for building a custom toast layout.

<Only platform="swift">

Add `.toaster()` once near the root. It overlays the toast stack at the bottom of the view and puts its `ToastManager` in the environment as `toastManager`. Call `show`, `success`, `info`, `warning`, `error` or `loading` to add a toast, `update` to change it and `dismiss` to remove it.

```swift
import SwiftUI

struct ContentView: View {
  @Environment(\.toastManager) private var toasts

  var body: some View {
    Button("Save") {
      toasts.success("Saved", description: "Your changes are stored.")
    }
    .buttonStyle(.variant())
    .toaster()
  }
}
```

## Accessibility

- Each toast has the `alert` role and a live region that is `polite`, or `assertive` for `priority: "high"`.
- New toasts are announced with their title and description; high-priority announcements are not queued.
- A `dismiss` accessibility action and the escape gesture close the toast.
- Toasts stacked behind the front one are hidden from VoiceOver and TalkBack.
- The close button has the label "Close toast" and the type icon is hidden from assistive technology.
- Animations respect the system reduce motion setting.

## Notes

- Uses `bg-popover`, `text-foreground`, `text-muted-foreground` and tint tokens `bg-green-500`, `bg-primary`, `bg-orange-500` and `bg-destructive` for the icons.
- Light and dark colors follow the system appearance; dark mode drops the border.
- Toasts respect the bottom safe area inset.
- `FullWindowOverlay` is used on iOS only; Android renders the viewport directly.
