`CodeBlock` shows code and command output in a rounded surface. Put the code in `CodeBlockContent` and, optionally, a `CodeBlockHeader` with a title and actions above it and a `CodeBlockFooter` below it.

Pass a string to `CodeBlockContent` for plain output, or a list of `CodeBlockLine` when lines need a state or highlighted tokens. `useHighlightedCode` highlights with [Shiki](https://shiki.style) and keeps working while the code streams in.

## Installation

### CLI

```bash title="Terminal"
npx shadcn@latest add @esuiss/code-block
```

Works in any project with a `components.json`. See [Installation](/docs/installation#add-components) for the one-line registry setup. Or use the [suiss/ui CLI](/docs/cli):

```bash title="Terminal"
npx @esuiss/ui@latest add code-block
```

### Manual

1. Install the dependencies, add the [`cn` helper](/docs/installation#the-cn-helper) and the [Button](/docs/components/button) component:

```bash title="Terminal"
npm install class-variance-authority shiki
```

2. Copy the source into `components/ui/code-block.tsx`:

<ComponentSource path="components/ui/code-block.tsx" />

3. For syntax highlighting, copy the highlighter into `lib/highlighter.tsx`:

<ComponentSource path="lib/highlighter.tsx" />

4. Copy the hook into `hooks/use-highlighted-code.ts`:

<ComponentSource path="hooks/use-highlighted-code.ts" />

5. Update the import paths to match your project.

## Usage

```tsx
import {
  CodeBlock,
  CodeBlockActions,
  CodeBlockContent,
  CodeBlockCopyButton,
  CodeBlockFooter,
  CodeBlockHeader,
  CodeBlockLine,
  CodeBlockTitle,
} from "@/components/ui/code-block"
```

```tsx
<CodeBlock>
  <CodeBlockHeader>
    <CodeBlockTitle>Terminal</CodeBlockTitle>
    <CodeBlockActions>
      <CodeBlockCopyButton value={output} />
    </CodeBlockActions>
  </CodeBlockHeader>
  <CodeBlockContent>{output}</CodeBlockContent>
</CodeBlock>
```

A string child renders as a single text node, so streamed output stays cheap. Line numbers and diff markers are left out of a selection, and the content always reads left to right, while the header follows the page direction.

### Syntax highlighting

`useHighlightedCode` returns one React node per line, ready for `CodeBlockLine`.

<ComponentPreview name="code-block-highlighting" />

```tsx
const lines = useHighlightedCode(code, "json")

<CodeBlock>
  <CodeBlockContent>
    {lines.map((line, index) => (
      <CodeBlockLine key={index}>{line}</CodeBlockLine>
    ))}
  </CodeBlockContent>
</CodeBlock>
```

Shiki runs on its JavaScript regex engine, so there is no WASM to load.

### Languages

Each language loads on first use. The list lives in `lib/highlighter.tsx` and ships with `bash`, `css`, `diff`, `html`, `javascript`, `json`, `jsx`, `markdown`, `python`, `sql`, `tsx`, `typescript` and `yaml`, plus aliases such as `ts`, `js`, `sh` and `yml`. Any other language renders as plain text.

<ComponentPreview name="code-block-languages" />

### Terminal output

Pass `"ansi"` as the language to turn escape codes into colors. Colors do not carry over from one line to the next.

<ComponentPreview name="code-block-ansi" />

### Streaming

While code streams in, the hook tokenizes only the new lines. Unchanged lines keep their nodes, so React skips them.

<ComponentPreview name="code-block-streaming" />

### Server rendering

`highlightCode` is async and runs in a Server Component, which keeps Shiki out of the client bundle.

```tsx
import { highlightCode } from "@/lib/highlighter"

export async function ServerCode({ code }: { code: string }) {
  const lines = (await highlightCode(code, "tsx")) ?? code.split("\n")

  return (
    <CodeBlock>
      <CodeBlockContent lineNumbers>
        {lines.map((line, index) => (
          <CodeBlockLine key={index}>{line}</CodeBlockLine>
        ))}
      </CodeBlockContent>
    </CodeBlock>
  )
}
```

### CodeBlockContent

The `pre` and `code` pair that scrolls or wraps.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `React.ReactNode` | - | A string, or a list of `CodeBlockLine`. |
| `wrap` | `boolean` | `false` | Wraps long lines instead of scrolling. |
| `lineNumbers` | `boolean` | `false` | Numbers each line. A string child is split into lines. |
| `startLine` | `number` | `1` | The number of the first line when `lineNumbers` is set. |
| `tabIndex` | `number` | `0` | Keeps the content focusable so it scrolls by keyboard. |

Also accepts the props of `React.ComponentProps<"pre">`.

</ApiPart>

One line of code.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |

Also accepts the props of `React.ComponentProps<"span">`.

</ApiPart>

### CodeBlockFooter

A row below the content, such as for a Show more button.

Also accepts the props of `React.ComponentProps<"div">`.

### useHighlightedCode

```tsx
const lines = useHighlightedCode(code, language)
```

Returns one React node per line. Until the first pass finishes, and for a language outside the list, it returns plain lines.

| Argument | Type | Description |
| --- | --- | --- |
| `code` | `string` | The code to highlight. A trailing newline is ignored. |
| `language` | `string` | A language or alias from `lib/highlighter.tsx`, or `"ansi"`. |

## Accessibility

- `CodeBlockContent` renders a `pre` with a `code` element and always sets `dir="ltr"`, so code reads left to right on a right-to-left page.
- The content has `tabIndex={0}` so keyboard users can focus and scroll it. Pass `tabIndex={-1}` to remove the tab stop.
- Floating actions appear when focus is inside the block, not only on hover.
- Line numbers are hidden from screen readers.
- Added and removed lines carry a `+` or `−` marker as well as a tint, so the change does not rely on color.
- `CodeBlockCopyButton` is labelled "Copy" and announces "Copied" after a successful copy.
- Give a wrap toggle `aria-pressed`, and a Show more button `aria-expanded` with `aria-controls` pointing at the content `id`.

## Notes

- Styling hooks: `data-slot="code-block"`, `code-block-header`, `code-block-title`, `code-block-actions`, `code-block-copy-button`, `code-block-content`, `code-block-code`, `code-block-line` and `code-block-footer`. The root exposes `data-variant` and `data-size`, and each line exposes `data-variant`.
