`InputGroup` is the container that draws the field's background, border and focus ring. Inside it, place one control, either `InputGroupInput` or `InputGroupTextarea`, and one or more `InputGroupAddon` elements. An addon can hold icons, `InputGroupText`, `InputGroupButton` or a `Kbd`, and is placed before, after, above or below the control with its `align` prop.

Use an input group when supporting content belongs inside the field, such as a search icon, a currency symbol, a clear button or a send button. For a plain field, use `Input`; for a field with a filterable list of options, use `Combobox`, which is built on this component.

## Usage

<Code lang="tsx" code={"import { InputGroup, InputGroupAddon, InputGroupButton, InputGroupText, InputGroupInput, InputGroupTextarea } from \"@/components/ui/input-group\""} />

<Code lang="tsx" code={"<div className=\"w-96\">\n  <InputGroup>\n    <InputGroupInput placeholder=\"Search...\" />\n    <InputGroupAddon>\n      <MagnifyingGlassIcon />\n    </InputGroupAddon>\n    <InputGroupAddon align=\"inline-end\">12 results</InputGroupAddon>\n  </InputGroup>\n</div>"} />

Addons are positioned with CSS order, so you can place them before or after the control in your markup. `inline-start` and `inline-end` sit beside the control; `block-start` and `block-end` sit above or below it and make the group grow to fit. Clicking an addon outside its buttons focuses the group's `input`.

`InputGroupButton` defaults to `type="button"`, so it does not submit a surrounding form unless you set `type="submit"`. Set `aria-invalid` on the control to show the error style on the whole group. To dim a disabled group's addons, disable the control and set `data-disabled="true"` on `InputGroup`.

## Accessibility

- `InputGroup` and `InputGroupAddon` have the `group` role.
- Give the control an accessible name with a label or `aria-label`; placeholder text and addon text do not name it.
- Give icon-only buttons an accessible name with `aria-label`.
- Buttons in addons are reachable with Tab after the control.
- Set `aria-invalid` on the control to communicate a validation error.

## Notes

- Styling hooks: `data-slot` values `input-group`, `input-group-addon` and `input-group-control` (on the input or textarea). Addons set `data-align`, and buttons set `data-size`.
- The group's rounded corners grow when it contains a textarea or a block addon.
- Uses the `control`, `control-disabled`, `label-secondary`, `label-quaternary` and `danger` tokens.

`InputGroup` draws one control-colored field and places an `InputGroupInput` or `InputGroupTextarea` inside it with addons around. Addons can sit on the start or end of the same line (`inline-start`, `inline-end`), or above or below the input (`block-start`, `block-end`), which turns the group into a column.

The group shows the focus border while its input is focused, and reads the disabled and invalid state from a surrounding Field. Pressing an addon focuses the input.

## Usage

<Code lang="tsx" code={"import { InputGroup, InputGroupAddon, InputGroupButton, InputGroupText, InputGroupInput, InputGroupTextarea } from \"@/components/ui/input-group\""} />

<Code lang="tsx" code={"<View className=\"gap-4\">\n  <SearchDemo />\n  <InputGroup>\n    <InputGroupAddon>\n      <InputGroupText>https://</InputGroupText>\n    </InputGroupAddon>\n    <InputGroupInput placeholder=\"example.com\" autoCapitalize=\"none\" />\n    <InputGroupAddon align=\"inline-end\">\n      <InputGroupText>.com</InputGroupText>\n    </InputGroupAddon>\n  </InputGroup>\n  <InputGroup>\n    <InputGroupInput defaultValue=\"sk_live_51H8\" />\n    <InputGroupAddon align=\"inline-end\">\n      <InputGroupButton size=\"icon-xs\" accessibilityLabel=\"Copy\">\n        <Icon as={CopyIcon} />\n      </InputGroupButton>\n    </InputGroupAddon>\n  </InputGroup>\n  <InputGroup>\n    <InputGroupInput placeholder=\"Searching...\" />\n    <InputGroupAddon align=\"inline-end\">\n      <Spinner />\n    </InputGroupAddon>\n  </InputGroup>\n  <InputGroup invalid>\n    <InputGroupInput defaultValue=\"not-an-email\" />\n    <InputGroupAddon align=\"inline-end\">\n      <InputGroupText>Invalid</InputGroupText>\n    </InputGroupAddon>\n  </InputGroup>\n  <InputGroup disabled>\n    <InputGroupInput placeholder=\"Disabled\" />\n    <InputGroupAddon>\n      <Icon as={MagnifyingGlassIcon} />\n    </InputGroupAddon>\n  </InputGroup>\n</View>"} />

Add children in any order; the group sorts start addons before the input and end addons after it. Put short labels such as a URL prefix or a unit in `InputGroupText`, and actions in `InputGroupButton`, a small rounded `Button` that defaults to the `ghost` variant and `xs` size.

Use a `block-end` addon with `InputGroupTextarea` for a footer row, for example a character count and a send button. Set `invalid` or `disabled` on the group, or let a Field provide them.

## Accessibility

- The container has the `group` role.
- Addons are not separate accessibility elements; their text is not announced with the input, so give the input an `accessibilityLabel` that includes needed context.
- Icon-only buttons need an `accessibilityLabel`.

## Notes

- Uses `bg-control`, `border-focus`, `border-danger` and `bg-control-disabled` tokens; the invalid tint is stronger in dark mode.
- Light and dark follow the system appearance.
