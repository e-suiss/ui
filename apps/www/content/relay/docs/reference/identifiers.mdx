## ID format

External IDs are a type prefix plus 26 lowercase Crockford base32 characters encoding a UUIDv7:

```text
ntf_01jb8x2k4m6n8p0q2r4s6t8v1b
```

- Time-ordered, case-insensitive and URL-safe.
- The prefix identifies the type and is checked when the ID is resolved.
- IDs are opaque; do not parse them.
- Record time comes from the database clock.

| Prefix | Object |
|---|---|
| `ten_` | Tenant |
| `stn_` | Sub-tenant |
| `sub_` | Subscriber (human recipient) |
| `agt_` | Agent recipient |
| `rcp_` | Recipient, without saying which kind |
| `evt_` | Event (intake) |
| `ntf_` | Notification |
| `dlv_` | Delivery |
| `att_` | Delivery attempt |
| `dle_` | Delivery ledger event |
| `oev_` | Outbound event |
| `wfl_` | Workflow |
| `tpl_` | Template |
| `wp_` | Waitpoint |
| `wpr_` | Waitpoint reply |
| `mbx_` | Mailbox |
| `mbr_` | Mailbox record |
| `dlq_` | Dead-letter record |
| `fan_` | Fan-out or batch |

Workflows are addressed in the API by their readable key (slug), such as `order-shipped`, not by ID.

## Event naming

- Every event name has the form `noun.verb_past` and lives in one catalog. One concept never has two names; for example, `cancelled` is the only spelling.
- The catalog is written as AsyncAPI 3.1 with JSON Schema 2020-12. Each event type's schema is versioned, and a schema change opens a new version of that type.
- The same catalog feeds the webhook portal, SDKs and webhook verifiers.
- A tenant's own event types for the `webhook` channel use the same catalog structure, scoped to the tenant.

## Headers

| Header | Direction | Meaning |
|---|---|---|
| `Authorization: Bearer` | Request | Access token or subscriber token |
| `Idempotency-Key` | Request | Required on every mutating request |
| `Idempotency-Replayed` | Response | `true` when the response is a replay |
| `Request-Id` | Response | On every response |
| `Relay-Version` | Request | Dated API version, `YYYY-MM-DD` |
| `Relay-Beta` | Request | Turns on a beta feature |
| `Relay-Batch-Max-Events` | Response | Batch row limit |
| `Relay-Batch-Max-Recipients-Per-Event` | Response | Recipients per event limit |
| `RateLimit`, `RateLimit-Policy` | Response | Rate limit state and policy |
| `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` | Response | Rate limit state, for compatibility |
| `Retry-After` | Response | Delta seconds |
| `Deprecation`, `Sunset`, `Link rel="deprecation"` | Response | Version retirement notices |
| `webhook-id`, `webhook-timestamp`, `webhook-signature` | Outbound webhook | Signature profile |
| `webhook-delivery: abort-message` | Consumer response | Stop retrying this message |
