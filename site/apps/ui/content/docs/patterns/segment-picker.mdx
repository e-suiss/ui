`SegmentPicker` presents a small set of mutually exclusive options, such as a time period or a view mode. On desktop it renders a suiss/ui `ToggleGroup` in which exactly one segment stays pressed; clicking the pressed segment keeps it selected. On mobile (below `48rem`, via `useIsMobile`) it renders a `NativeSelect` so the choice fits narrow screens and uses the platform picker.

Each `SegmentPickerItem` becomes a toggle on desktop and an `option` on mobile. Use it for two to five short options that change how content is displayed.

## Usage

<Code lang="tsx" code={"import { SegmentPicker, SegmentPickerItem } from \"@/components/patterns/segment-picker\""} />

<Code lang="tsx" code={"<SegmentPicker defaultValue=\"week\" aria-label=\"Period\">{periods}</SegmentPicker>"} />

- The value is uncontrolled by default; use `defaultValue`, or `value` with `onValueChange` to control it. `onValueChange` fires only when the selection changes.
- Without a value, no segment is pressed and the mobile select shows an empty disabled option.
- On mobile each option shows `label`, then `aria-label`, then string children, then `value`. Give icon-only segments an `aria-label`, and segments with mixed content a `label`.
- `variant` and `spacing` apply only on desktop. On mobile, `lg` falls back to the default size.
- With `name`, desktop renders a hidden input so the value is submitted with a form.

## Accessibility

- On desktop the root is a `group` named by `aria-label`, and each segment is a button with `aria-pressed`.
- Disabled segments are disabled buttons and cannot be selected.
- On mobile the control is a native `select`.

## Notes

Styling hooks: `data-slot="segment-picker"` and `segment-picker-item`. `SegmentPickerItem` throws when used outside `SegmentPicker`.
